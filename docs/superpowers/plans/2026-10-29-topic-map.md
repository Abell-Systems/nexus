# Technology Topic Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the plain-language topic map (entry → topic summary → four detail views) for two topics, batteries and solar, from versioned aggregate results computed offline.

**Architecture:** Python computes one aggregate JSON per topic from the OEPM corpus (domain defines topic/sub-area, application computes the metrics, infrastructure reads the corpus and writes the file). The React frontend loads it through the existing verified loader (SHA-256 from a build-time manifest) and renders the views; sentences are generated by pure functions with tests. The static staging image keeps answering 404 for the topic data until D4 is resolved.

**Tech Stack:** Python 3.12 (pytest, ruff, mypy), React 19 + TypeScript 6 + Vite + Vitest + Testing Library, nginx static image. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-29-technology-topic-map-product-design.md` (approved 2026-10-29). Read it first; section numbers below refer to it.

## Global Constraints

- Clean Architecture: domain → application → infrastructure; tests named `shouldXWhenY`; mock only at architectural boundaries.
- Before every push of Python: `ruff check backend/src/main backend/test scripts` and `mypy backend/src/main --ignore-missing-imports` pass. Before every push of frontend: `npm run typecheck`, `npm run lint`, `npm test` in `frontend/`.
- Unit of analysis is the O4 unit: the publication identifier with the union of the codes of its earliest publication date. Never count records. Year 2010 has no documents: skipped, never counted as zero.
- Expected count is ADR 0038 E3, within years: `E(T,X) = Σ_y n_T(y)·n_X(y)/N(y)` over years with documents.
- "Menos de lo esperado" rows: observed `O ≥ 30` and `E ≥ 30` and `O/E < 0.8`; ordered alphabetically by plain name; no score, no top-N. Parameters are provisional and live in one constant each.
- Never-co-classified pairs (O = 0) are never computed into a served file nor shown. The fictitious block is not built.
- "One applicant dominates" appears only when one applicant is ≥ 30 % of the documents of 2024 and 2025. The text never says "crece" or "decrece".
- Five items visible per list, the rest behind "Ver N más". Numbers use `.` as thousands separator. UI text is Spanish only, in one module. No IPC code is visible (a code may appear only in a `title` attribute).
- The browser computes no metric; it draws what the result states. No router and no new dependency (contract of vertical 3).
- Topic data is served on demand and is **not** served from the static staging image: `deploy/nginx-static.conf` answers 404 for it, as for the unobserved-pairs file.
- Definitions carry a `reviewed` flag per plain name; a client build refuses topics with unreviewed names.
- Do not publish derived figures or identifier lists outside the development environment: D4 is unresolved.

## Review Focus

- A topic with no qualifying "menos de lo esperado" rows: the view says so instead of drawing an empty chart (Task 4 test, Task 10 test).
- Tied peak years and a year without documents (2010) in the evolution sentence (Task 9 tests).
- Two applicant rules that could match one name, and a name no rule resolves (Task 5 tests).
- Topic file missing (404), hash mismatch, or unreviewed names: the topic shows "datos no disponibles", never a partial page (Tasks 6, 8, 10 tests).
- A sub-area with zero units and keyboard operation of the "Cómo leer esto" dialog (Task 10 tests).
